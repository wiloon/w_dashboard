# ADR-013: 面板密度——番茄钟与时钟合并为顶部「当下（Now）」状态区

## Status

Accepted（macOS 先落地；Linux Slint 主窗口 + KDE plasmoid 待跟进。不改变 ADR-001 的
"无后端 / 无数据库"、ADR-002 的两端独立原生实现、ADR-008 的规格驱动；对 ADR-012
「番茄钟置顶」的理由做了收窄解释，见 Decision）

## Context

**问题**：主窗口把信息竖着堆成一列卡片（番茄钟 / Repos / chezmoi / Clocks / Weather，SDD §9）。
其中 **Clocks 卡只有北京、纽约两个时钟**，一整行宽度里大片留白；番茄钟卡占了一整块高度，
内容却只有一行 phase + 一行时间 + 一条横向进度条 + 两个按钮。窗口纵向空间被这两张"内容稀疏
但各占一行"的卡片吃掉不少。

**触发**：作者 2026-09-09 提出——"番茄钟区域和时钟区域可以合并；时钟那一行有大量空闲的列。
另外番茄钟可以把横向进度条换成环形进度条，省横向空间。这类需求要不要写一个设计决策？
我现在在 macOS，就只改 macOS 版本，设计决策留给 Linux 版本参考。"

**约束**：

- SDD §9 定义了**五个分区、从上到下、顺序两端一致**（ADR-002 两端独立实现、ADR-008 规格驱动，
  一致性靠规格而非同一份产物）。
- ADR-012 明确写了番茄钟面板"置于窗口最上面，因为它是唯一需要主动操作的分区"。
- 番茄钟的面板强提醒——`*Ended` 的高亮边框、早晨提醒（morning nudge，§11.4 步骤 8）——
  不能因为合并而被稀释。
- 只改 macOS。Linux 端现在有两个 UI 面：**Slint 主窗口**（对应 macOS 主窗口，本 ADR 的跟进对象）、
  **KDE plasmoid**（`app-linux/plasmoid/`，一个面板小组件，显示北京时间 + 番茄钟 phase，对应的是
  macOS 菜单栏项而非主窗口——它已经把"phase + 北京时钟"并在一个紧凑元素里，本身**不需要因本 ADR 改动**，
  反倒印证了"番茄钟 + 时钟归一组"这个方向）。所以"Linux 待跟进"特指 Slint 主窗口。

**这不是什么**：不是重排信息顺序（番茄钟仍第一、仍最先看到），不是改番茄钟的纯逻辑
（`progress` 字段语义、测试向量一律不动），不是给番茄钟加新功能。

## Options Considered

### 一、顶部两张稀疏卡片怎么处理

| 方案 | Pros | Cons | 何时合适 |
|------|------|------|----------|
| A. 维持现状：五张独立卡片 | IA 最简单；两端已对齐 | 纵向浪费；Clocks 卡横向留白刺眼 | 认为分区必须一一对应独立卡片 |
| B. 时钟并入窗口标题行 + 番茄钟瘦成单行 | 回收纵向最多；交互 / 只读彻底分离 | 标题行在 `minWidth 760` 下略挤；丢时钟的日期行；番茄钟单行在窄窗口里也会挤 | 想最大化回收纵向、且接受标题行承载信息 |
| **C. 番茄钟 + 时钟合并为一张顶部「当下（Now）」卡片**（选中）：左半番茄钟（环形进度 + 按钮），右半时钟 | 省一张卡；"我此刻该做什么 + 现在几点"是同一类瞬时信息，归组自然；番茄钟仍在最顶、仍最显眼 | 一张卡里混了交互控件与只读读数——靠子区域视觉分隔 + 强提醒只作用于番茄钟子区域来化解 | 想适度回收纵向、且认可"瞬时状态"归为一组 |
| D. 番茄钟单行置顶，Clocks 与 Weather 并一行 | 保留分区顺序，改动最小 | Weather 卡较宽（当前天气 + N 日预报横向列表），与时钟并排易挤 | 时钟与天气都很窄时 |

### 二、番茄钟进度条形态（与合并正交，一并定）

| 方案 | Pros | Cons |
|------|------|------|
| 横向 `ProgressView` / 进度条（现状） | 各端 UI 框架原生 | 占横向空间——合并后番茄钟只有半张卡宽，横条更挤 |
| **环形进度环**（选中）：`mm:ss` / `+mm:ss` 居中，环色随 phase，`*Ended` 整环填满并变色 | 直径 ~64pt，横向占用小，与"半张卡宽"匹配；时间居中，一眼可读 | 两端各画一份圆弧（SwiftUI `Circle().trim` / Slint `Path` 圆弧）——极薄的展示逻辑 |

## Decision

选 **方案 C + 环形进度环**。

### 顶部「当下（Now）」卡片

替代原 SDD §9 的第 1 分区「Pomodoro」与第 4 分区「Clocks」，合为一张卡，置于窗口最上面：

- **左半——番茄钟子区域**：
  - 环形进度环，中心显示剩余 `mm:ss`（`*Ended` 显示 `+mm:ss` 超时）；环的进度 = `pomodoro_view` 的
    `progress`（0.0–1.0），环色随 phase（Idle 灰 / Focus 绿 / Break 蓝 / FocusEnded 红 / BreakEnded 橙）。
  - phase 标签（Idle / Focus / Break / Focus done / Break done）在环下方或环右侧。
  - 主切换按钮（ADR-012 「Next」）+ `Stop`（`Idle` 时禁用），语义与 SDD §9 第 1 项完全不变。
  - `pomodoro.enabled == false` 时**左半整体隐藏**，卡片退化为纯时钟（等同旧 Clocks 卡）。
- **右半——时钟子区域**：每个配置时区一列（label + 当前时间）。日期行可省略，或缩为小字 / hover
  （macOS `.help`）查看——北京 / 纽约与本地日期基本同天，影响小。
- **强提醒的作用范围收窄到番茄钟子区域**：`*Ended` 的高亮边框、早晨提醒的琥珀色提示，**只包住左半
  番茄钟子区域**，不波及整张卡、不波及右半时钟。这是本 ADR 对 ADR-012「番茄钟置顶因为它唯一需要
  操作」理由的落实——合并后它仍在最顶、仍最先看到、强提醒仍聚焦在它身上，置顶的初衷没有被破坏。

### 分区计数的措辞调整

SDD §9 从"五个分区"改为**四个视觉分区**（当下 / Repos / chezmoi / Weather），但**信息条目仍是 5 项**
（§1 概述不变）：番茄钟仍是逻辑上的第 1 项、仍置顶，只是与时钟共用一张卡。顺序两端一致的约束不变。

### 落地范围与顺序

- **macOS 先实现**（本 ADR 落地时一并改 `app-macos`）。
- **Linux Slint 主窗口、KDE plasmoid 待跟进**——本 ADR + SDD §9 为其提供参照。两端都落地前，
  SDD §9 标注"macOS 已合并，Linux 待跟进"。SDD §9 原本就允许"布局细节各端适配"，若 Slint /
  plasmoid 的布局能力撑不住这个合并，各端可回退到"番茄钟单行置顶 + 时钟单独卡"，信息顺序不变即可。

## Rationale

1. **Clocks 卡的横向留白是真浪费**——北京 / 纽约两个时钟撑不起一张整宽卡片，而番茄钟卡内容也稀疏。
2. **番茄钟和时钟都是"瞬时状态"**（现在几点、这个时段还剩多久），归为一组符合直觉；Repos / chezmoi /
   Weather 是"采集快照"，性质不同，留在下方各自成卡。KDE plasmoid（`app-linux/plasmoid/`）与 macOS
   菜单栏项早就把"北京时钟 + 番茄钟 phase"并在一起了——这个合并只是把同样的归组带到主窗口。
3. **不违背 ADR-012**：番茄钟仍在最顶、仍最先看到；把强提醒限定在子区域，交互显著性不降。
4. **环形进度环在窄区域里比横条省空间**，且 `mm:ss` 居中比"进度条上方另起一行显示时间"更紧凑易读。
5. **只改 macOS 是作者当前的需求**；先写 ADR + 改 SDD 让 Linux 跟进时有依据（ADR-008 规格驱动）——
   这正是"这类需求要不要写设计决策"的答案：要，因为它动到了 SDD §9 的信息架构，且要跨端对齐。

## Trade-offs

- 一张卡里混了**交互控件 + 只读读数**——靠左右子区域的视觉分隔维持清晰。若日后番茄钟面板要加更多
  控件（时段计数、跳过、设置入口），半张卡放不下，可能得拆回独立分区（见 Revisit Trigger）。
- **两端在"合并已落地 / 未落地"期间视觉不一致**——可接受：信息架构（顺序、条目）仍一致，且 SDD §9
  有明确标注；两端本就是独立实现、允许布局各端适配（ADR-002 / SDD §9）。
- **时钟日期行收起**——需要看日期时得 hover（macOS）。北京 / 纽约与本地日期基本同天，影响小。
- **环形进度环两端各画一份**——SwiftUI `Circle().trim` / Slint `Path` 圆弧，极薄的展示逻辑，
  同 ADR-006「时钟由各端 UI 自行实现」的取舍：纯展示、无逻辑、不进向量。

## Consequences

- **Positive**：回收一张卡的纵向空间；顶部信息密度更合理；番茄钟 + 时钟归组清晰；番茄钟纯逻辑与
  测试向量零改动（环形进度环消费的还是同一个 `progress` 字段）。
- **Negative**：SDD §9 / §11.4、CONTEXT.md、task-spec 需同步；两端短期视觉不一致；环形进度环多一处
  两端各实现。
- **Mitigation**：
  - **SDD §9** 改为"当下 / Repos / chezmoi / Weather"四视觉分区，番茄钟仍列为逻辑第 1 项，
    加"macOS 已合并、Linux 待跟进；各端可回退"标注。
  - **SDD §11.4 步骤 2「面板」** 更新为：环形进度环 + 顶部「当下」卡片左半区，强提醒只作用于番茄钟子区域。
  - **SDD §5.6 / §11.2** 的 `progress`（0.0–1.0）语义**不变**；`pomodoro/` 与 `pomodoro-transition/`
    测试向量**不动**。
  - **CONTEXT.md**「番茄钟」「时钟」词条各补一句：在主窗口顶部合为「当下（Now）」区。
  - **task-spec 新增 M9「顶部『当下』区：番茄钟 + 时钟合并 / 环形进度」**——记录 macOS 已改、
    Linux（Slint + plasmoid）待跟进。

## Revisit Trigger

- 番茄钟面板要加更多控件（时段计数、跳过、设置入口）——顶部半张卡放不下，重新评估是否拆回独立分区。
- 配置的时钟数量变多（> 3–4 个）——时钟子区域撑破半张卡，重新评估合并是否还成立。
- Linux 端跟进时发现 Slint / plasmoid 布局能力撑不住这个合并——各端回退到"番茄钟单行置顶 +
  时钟单独卡"，SDD §9 已允许布局各端适配。
- 想给主窗口再塞一类"瞬时状态"信息——先问它是否也属于「当下」区，避免这张卡无限膨胀。
