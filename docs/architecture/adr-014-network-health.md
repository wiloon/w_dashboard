# ADR-014: 网络健康检测——本机所连网络的延迟 / 丢包 / 抖动 / 速率

## Status

Accepted（v1 先落地 macOS，Linux 待跟进；不改变 ADR-001 的"无后端 / 无数据库"、ADR-002 的两端独立原生实现、
ADR-003 的子进程调用风格、ADR-008 的规格驱动。公网测速 / 探测端点视同 ADR-005 天气 API 的"直接调公网"例外）

## Context

**问题**：作者常带孩子去商场，连商场提供的公共 Wi-Fi 热点；有些热点很差。希望在 w_dashboard 上直接看到
**当前所连网络的健康状况**：到国内主要节点、国外主要节点、到家（`home.wiloon.com`）的延迟，以及简单测速。

**触发**：作者原话——"我希望在 w Dashboard 上能够看到我连接的网络的健康状况……到我家里的延迟是多少？
或者到国内的主要节点的延迟，或者到国外主要节点的延迟。然后它的速率，可能要做一个简单的测速。"

**本次已确认的取舍**（见会话问答，2026-10-01）：

| 问题 | 结论 |
|------|------|
| 测速节点 | 国内**只用 Apple `mensura.cdn-apple.com`**（实测在大陆有 CDN 节点，上下行都有接口）；国外用 **Cloudflare `speed.cloudflare.com`** |
| 测速量 | 每个方向**最多 8 秒或 25 MB**，先到先停；一次完整测速约 50～100 MB |
| 测速触发 | **只手动**（按钮），从不自动跑 |
| 轻量探测（延迟/丢包/抖动） | **自动**：启动、每 60 秒（可配）、网络切换时；另有手动`Re-check` |
| 到家 | v1 **不测到家速率**；只用 **TCP 握手**测到 `home.wiloon.com:443` 的延迟 |
| HomeLab 测速端 | v1 不做；v2 再议（HomeLab 有 nginx，也可 iperf3） |
| Wi-Fi 信息 | 读 SSID 需要 macOS 定位权限——**同意授权** |
| 健康等级阈值 | 采纳建议值（见 SDD §12.4） |
| 历史 | **不存历史**，只显示最近一次结果（内存） |
| 界面位置 | **不放首页**；主窗口顶部加**标签切换** `[ Dashboard | Network ]` |
| 平台 | **先做 macOS**；规格与向量一次写全，Linux 后续跟进 |
| 测哪条路径 | **只测实际路径**：跟随系统默认路由与系统代理（WireGuard / Clash 开着时，测的是经隧道/代理后的真实体验） |

**实测环境观察**（作者 MacBook，2026-10-01）：默认路由走 WireGuard（`utun4`），同时运行 Clash Verge；
Wi-Fi 网卡 `en0` 的网关 `192.168.207.254` ping 5 包 0% 丢包但 RTT 8～59 ms；`home.wiloon.com` 443/80/8443
端口 TCP 可连，但 HTTP(S) 请求无正常响应——所以"到家"只能用 TCP 握手而非 HTTP。

**约束（不变）**：无后端 / 无数据库（ADR-001）；两端独立实现（ADR-002）；纯逻辑进测试向量、副作用留在采集入口/UI 层
（ADR-008、SDD §10.1）；联网/子进程一律超时 + 失败降级（AGENTS.md）。

## Options Considered

### 一、延迟采样方法

| 方案 | Pros | Cons |
|------|------|------|
| A. ICMP `ping` 子进程 | 经典、两端都有；输出可解析（ADR-003 风格） | 公共 Wi-Fi 常封 ICMP；Clash TUN 模式下 ICMP 行为不可控；不走 HTTP 代理 |
| B. TCP 握手耗时 | 无需特权；几乎不被封 | Clash TUN **fake-ip** 模式下握手在本机就完成，测出≈0 ms，无意义；不走系统 HTTP 代理 |
| **C. HTTP 往返时延（复用连接的 TTFB）** | 走系统代理与隧道，**真实反映"实际路径"**；443 几乎不被封；原生 HTTP 库即可 | 含极少量服务端处理时间；需要目标有轻量 HTTP 资源 |

→ **远端目标默认 C（`method = "http"`），允许按目标选 B（`method = "tcp"`）**——"到家"用 B（作者指定；且其 HTTP 不通）。
**网关用 A**：网关在本地网段、不经代理，ICMP 最直接；网关封 ICMP 时自动从健康判定中剔除（SDD §12.4）。

### 二、测速方法

| 方案 | Pros | Cons |
|------|------|------|
| **A. 公网 HTTP 下载/上传（单流，限时限量）** | 无需自建服务；原生 HTTP 库；走 443 | 单流在高 BDP 跨境路径上可能低估；依赖公网端点（Apple 端点无公开文档） |
| B. iperf3 | 专业，UDP 可直接测抖动/丢包 | 要自建服务端 + 本机装客户端；非常规端口常被公共 Wi-Fi 封 |
| C. macOS `networkQuality` | 系统自带，含 RPM | 仅 macOS，Linux 无对等物；不可控 |

→ **v1 选 A**。B 留给 v2（HomeLab）。

### 三、测量路径

| 方案 | 说明 |
|------|------|
| 只测热点本身（绑定物理网卡、绕过代理） | 反映热点质量，但不反映开着 VPN 时的真实体验 |
| **只测实际路径**（选中） | 跟随默认路由 + 系统代理，反映"我此刻上网的真实体验" |
| 两者都测 | 信息最全，实现/界面翻倍 |

**唯一例外**：Captive Portal 检测与 Wi-Fi 链路信息天然属于物理网络——Captive 检测绑定 Wi-Fi 接口且不走代理
（未认证的热点上，隧道本身就建不起来，走隧道去测无意义）。

### 四、界面位置

独立窗口 / 侧边栏 / **顶部标签切换**（选中，作者选择）。主窗口顶部加分段控件 `[ Dashboard | Network ]`，
`Dashboard`即现有全部内容（ADR-013 的布局不变）。

## Decision

新增「网络健康（Network Health）」模块：

1. **轻量探测**（自动）：网关（ping）、国内 / 国外 / 家 各组目标（HTTP RTT 或 TCP 握手），每目标每轮 N 次采样，
   得出丢包率 / 中位延迟 / 抖动；Captive Portal 检测；派生一个**健康等级**。
2. **测速**（手动）：国内（Apple）与国外（Cloudflare）各测下行 + 上行，单流、限时限量。
3. **链路信息**（UI 层采集，不进向量）：当前接口类型、是否经 VPN、是否开系统代理、Wi-Fi SSID / RSSI / 噪声 / 速率 / 信道 / 频段。
4. **纯逻辑进测试向量**：ping 输出解析、采样统计、分组汇总、Captive 判定、健康等级决策表、吞吐量换算。
5. **不存历史**；结果只在内存，重启即空。

精确规格见 SDD §12。

## Rationale

1. **属于"本机状态"**：所连网络的质量是本机此刻的状态，与 git/天气同类，不改变 ADR-001 的应用定位；
   公网探测/测速端点与天气 API 同属"直接调公网"，不引入后端。
2. **"实际路径"是作者的明确选择**：作者外出时常开 WireGuard 回家 + Clash；他关心的是此刻真实上网体验。
   HTTP RTT 是唯一能稳定穿过系统代理与 TUN fake-ip 的采样方法。
3. **轻重分离**：探测每轮流量只有几十 KB，可以自动跑；测速一次 50～100 MB，在公共 Wi-Fi / 手机热点上必须由人决定。
4. **纯逻辑进向量**延续 ADR-008：统计口径（中位数、抖动定义、取整）与健康阈值是两端最容易悄悄分叉的地方，必须由向量锁死。

## Trade-offs

- 远端延迟含少量服务端处理时间（HTTP TTFB），比纯网络 RTT 略大；健康阈值已按此留余量。
- 开着全局 WireGuard 时，"国内/国外"都是"热点 → 家 → 目标"，**看不出热点本身是否差**——只能靠网关延迟与
  Wi-Fi 链路信息辅助判断。这是选"实际路径"的已知代价。
- Apple `mensura` 端点无公开文档，可能变更；Cloudflare 在大陆基本走海外线路。地址全部可配置，失败只局部降级。
- 单流测速在高 BDP 跨境路径上可能低估国外带宽。
- macOS 读 SSID 需要定位权限，且只在打包为 `.app`（有 `Info.plist`）时可申请；`swift run` 开发态拿不到 SSID，降级为只显示信号/速率。
- 主窗口从单页变为两个标签，首页结构多一层。

## Consequences

- **Positive**：在公共热点上一眼看出"能不能用、卡在哪一段"（未认证 / Wi-Fi 这一跳差 / 出口差）；手动测速给出上下行数字。
- **Negative**：两端各多一个模块；macOS 多一项系统权限；多依赖两个非自有公网端点。
- **Mitigation**：
  - **SDD 新增 §12「网络健康」**（模型 / 配置 / 采样与统计口径 / 健康决策表 / 测速流程 / UI 职责 / 非目标），原 §12–§14 顺延为 §13–§15；§4 加 `[network]`；§9 加标签切换。
  - **新增测试向量**：`ping-output/`、`probe-stats/`、`probe-group/`、`captive-portal/`、`network-health/`、`throughput/`。
  - **task-spec 加 M10**：规格 + 向量 → macOS 实现 → Linux 待跟进。
  - `config.example.toml` 加 `[network]`；`CONTEXT.md` 加术语；`Info.plist` 加定位用途说明。

## Revisit Trigger

- 想测"热点本身"与"经隧道"的差异 → 重新评估方案三的"两者都测"。
- 要到家测速 / 更准的测速 → v2：HomeLab nginx 测速端点或 iperf3（另开 ADR 或修订本 ADR）。
- 想看一段时间内的网络质量曲线 → 触及 ADR-001 / SDD 非目标"历史"，需重新评估是否引入状态文件。
- Apple / Cloudflare 端点失效或长期不可达 → 换端点（改配置默认值 + 本 ADR）。
